# Software Deployment

## CI

[`.github/workflows/ci.yml`](../.github/workflows/ci.yml):

- `./gradlew clean test jacocoTestReport`
- Gateway contract tests
- SonarCloud: set repo secret `SONAR_TOKEN`; CI job `SonarCloud Code Analysis` runs `./gradlew sonar` on push/PR to `staging` and `main`
- Compose smoke / CD contract tests

## Deployment strategy

BidMart uses staging-first progressive promotion. VPS deployment workflows run after CI succeeds through `workflow_run`, while Heroku and Vercel use their managed automatic deployment flows with GitHub checks as the gate.

Detailed strategy and platform mapping: [`deployment-strategy.md`](./deployment-strategy.md).

## Monitoring deployment

**Local (compose):**

1. `docker compose up` starts `prometheus` + `grafana`.
2. Import dashboards from `monitoring/grafana/dashboards/`.
3. Verify targets: `http://localhost:9090/targets` — all `bidmart-*` jobs **UP**.

**Production (Heroku + Grafana Cloud):**

1. Deploy backend Heroku apps; gateway last.
2. Follow [monitoring/grafana-cloud/README.md](../monitoring/grafana-cloud/README.md).
3. Scrape config reference: [monitoring/grafana-cloud/alloy.config.river](../monitoring/grafana-cloud/alloy.config.river).
4. `USE_HEROKU_URLS=true ./scripts/verify-monitoring.sh` before enabling cloud scrape.
