# Heroku pipeline — staging vs production

BidMart uses **VPS Docker Compose** as the official backend (private gRPC). Heroku remains HTTP fallback and rubric evidence.

## App matrix

| Service | Production app | Staging app | Repo CD | Owner |
|---------|----------------|-------------|---------|-------|
| Auth | `bidmart-authentication-service` | `bidmart-authentication-service-staging` | `cd.yml` on `staging` / `main` | Team (owner) |
| Auction | `bidmart-auction-service` | `bidmart-auction-service-staging` | `cd.yml` on `staging` / `main` | Team (owner) |
| Catalogue | `bidmart-catalogue` | _request from owner_ | `cd.yml` → staging only today | Collaborator |
| Wallet | `bidmart-wallet-service-rust` | _request from owner_ | — | Collaborator |
| Order | `bidmart-order-and-notification` | _request from owner_ | — | Collaborator |
| Gateway | `bidmart-infrastructure` | _request from owner_ | — | Collaborator |

## Branch → environment

- `staging` branch → staging Heroku app (or VPS `bidmart-staging`)
- `main` branch → production Heroku app (or VPS `bidmart-prod`)

Auth CD resolves the target app in [bidmart-auth-service/.github/workflows/cd.yml](../../bidmart-auth-service/.github/workflows/cd.yml).

## Creating staging apps (owner)

```bash
heroku create bidmart-authentication-service-staging --stack container
heroku addons:create heroku-postgresql:essential-0 -a bidmart-authentication-service-staging
heroku config:set SPRING_PROFILES_ACTIVE=prod -a bidmart-authentication-service-staging
# copy non-secret config from production, use distinct DB and JWT for staging

heroku create bidmart-auction-service-staging --stack container
heroku addons:create heroku-postgresql:essential-0 -a bidmart-auction-service-staging
# HTTP only — do not enable gRPC on Heroku Common Runtime
```

## Collaborator request template

Send to app owner:

> Please add `<your-github>` as collaborator on Heroku app `<app-name>` and create `*-staging` with a separate Postgres addon. We need `staging` branch CD for integration tests; production gRPC runs on VPS only.

## Databases

- Never share production Postgres credentials with staging.
- VPS: separate compose volumes per `COMPOSE_PROJECT_NAME` (`bidmart-staging` vs `bidmart-prod`).
