# Software Design (Gateway)

## Gateway source layout

| Component | Path |
|-----------|------|
| Application | `src/main/java/.../BidmartGatewayApplication.java` |
| JWT filter | `security/GatewayJwtAuthenticationFilter.java` |
| Rate limit | `security/GatewayRateLimitFilter.java` |
| Identity body guard | `security/GatewayIdentityBodyGuardFilter.java` |
| Permission client | `security/AuthServicePermissionClient.java` |
| Route policy | `security/RoutePermissionPolicy.java` |
| Request logging | `security/GatewayRequestLoggingFilter.java` |

## SOLID

- **SRP:** Each filter handles one concern (auth, rate limit, body tampering, logging).
- **OCP:** New routes added in `application.yml` without changing filter implementations.
- **DIP:** `AuthPermissionClient` interface isolates gateway from auth HTTP details.

## Patterns (≥3)

### 1. Chain of responsibility (WebFlux filters)

Ordered gateway filters compose cross-cutting policies before proxying to downstream services.

### 2. Policy object

`RoutePermissionPolicy` maps routes to required permissions fetched from auth.

### 3. Anti-corruption / guard

`IdentityBodyConflictChecker` + `GatewayIdentityBodyGuardFilter` prevent client body `userId` from conflicting with JWT-derived identity (ADR-003).

### 4. Contract tests as living documentation

`src/test/java/.../Gateway*IntegrationContractTest.java`, `PlatformComposeContractTest.java`, `CdWorkflowContractTest.java` encode expected routes and compose services.
