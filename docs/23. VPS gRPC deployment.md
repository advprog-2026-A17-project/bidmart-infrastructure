# VPS gRPC deployment

BidMart production backend runs on the VPS as Docker Compose projects so auction can call catalogue and wallet over real private gRPC.

## Topology

| Environment | Compose project | Gateway URL | Local gateway port |
|-------------|-----------------|-------------|--------------------|
| Staging | `bidmart-staging` | `https://bidmart-staging.43.157.208.68.sslip.io` | `127.0.0.1:18000` |
| Production | `bidmart-prod` | `https://bidmart-prod.43.157.208.68.sslip.io` | `127.0.0.1:28000` |

Caddy is shared and runs once from `/opt/bidmart/edge`. It routes the two public hostnames to the corresponding localhost gateway ports.

Private service-to-service endpoints:

```env
CATALOGUE_GRPC_URL=http://catalogue-service:9091
WALLET_GRPC_URL=http://wallet-service:50051
```

Do not publish `9091` or `50051` to the host.

## First setup

On the VPS:

```bash
mkdir -p /etc/bidmart
```

Create these files from the committed examples and fill real secrets:

```bash
/etc/bidmart/staging.env  # from deploy/vps/env.staging.example
/etc/bidmart/prod.env     # from deploy/vps/env.prod.example
/etc/bidmart/edge.env     # optional; deploy-edge.sh creates defaults
```

Install Docker and Compose if missing. Keep credentials out of shell history where possible.

## Deploy order

From the infrastructure repo on a trusted local machine:

```bash
cd bidmart-infrastructure
deploy/vps/deploy.sh staging
deploy/vps/deploy-edge.sh
```

After staging is green:

```bash
deploy/vps/deploy.sh prod
deploy/vps/deploy-edge.sh
```

Each backend deploy:

1. Clones or fast-forwards all backend repos on the selected branch.
2. Copies `/etc/bidmart/<env>.env` to the remote infrastructure `.env`.
3. Runs `docker compose up -d --build`.
4. Runs private gRPC verification.
5. Runs monitoring verification.

## Verification

```bash
cd /opt/bidmart/staging/bidmart-infrastructure
./scripts/verify-grpc-private.sh
USE_DOCKER=true ./scripts/verify-monitoring.sh
BIDMART_GATEWAY_URL=https://bidmart-staging.43.157.208.68.sslip.io node scripts/functional-smoke.mjs
```

Repeat from `/opt/bidmart/prod/bidmart-infrastructure` for production with the production URL.

`verify-grpc-private.sh` checks:

- catalogue gRPC port is not host-published,
- wallet gRPC port is not host-published,
- auction container has the gRPC env vars,
- catalogue and wallet gRPC services are reachable from the Compose network via `grpcurl`.

## Rollback

Rollback one environment by checking out a known-good branch/commit on the VPS and rebuilding the affected service:

```bash
cd /opt/bidmart/prod/bidmart-infrastructure
git -C ../bidmart-auction-service-rust checkout <known-good-sha>
docker compose --env-file .env up -d --build auction-service
./scripts/verify-grpc-private.sh
node scripts/functional-smoke.mjs
```

For database-impacting releases, restore the relevant Compose volume from backup before restarting the service. Do not run destructive migrations without a backup.

## Heroku fallback

Heroku Common Runtime apps are kept as HTTP fallback and rubric pipeline evidence. They must not be treated as the official gRPC production runtime because the current public Heroku routing setup does not expose private service-to-service HTTP/2 gRPC between catalogue/wallet and auction.
