# BidMart Deployment Status

This project uses platform-managed deployments:

- Backend services: Heroku GitHub automatic deploys.
- Frontend: Vercel GitHub automatic deploys.
- Databases: Supabase Postgres.
- GitHub Actions: CI only. There are no repo-managed CD workflows.

## Live Services

| Service | Platform | URL | Status |
| --- | --- | --- | --- |
| Frontend | Vercel | https://bidmart-frontend.vercel.app | Live |
| Auth | Heroku | https://bidmart-authentication-service-5f40f293e67d.herokuapp.com | Live app, Supabase auth DB configured |
| Auction | Heroku | https://bidmart-auction-service-c30c7668b800.herokuapp.com | Live app, Supabase auction DB configured |

## Pending Services

These services should keep CI ready, but production deployment/config should wait for the owning devmates:

- Catalogue
- Gateway / infrastructure
- Order and notification
- Wallet

## Current Cross-Service Wiring

Auth:

- `AUTH_EMAIL_VERIFICATION_BASE_URL=https://bidmart-frontend.vercel.app/verify-email`
- `SPRING_DATASOURCE_URL` points to the auth Supabase database.

Auction:

- `DATABASE_URL` points to the auction Supabase database.
- `CATALOGUE_SERVICE_URL` and `WALLET_SERVICE_URL` are already set on Heroku, but should be verified against the final live catalogue and wallet apps before production use.

Frontend:

- Vercel production URL is ready.
- `VITE_API_BASE_URL` should point to the public gateway URL once the gateway/infrastructure service is finalized.
- Do not point `VITE_API_BASE_URL` directly to auth or auction; the frontend calls multiple `/api/v1/...` services through the gateway contract.

Gateway / infrastructure, when ready:

- Set `AUTH_SERVICE_URL` to the live auth URL.
- Set `AUCTION_SERVICE_URL` to the live auction URL.
- Set `CATALOGUE_SERVICE_URL`, `WALLET_SERVICE_URL`, and `ORDER_SERVICE_URL` after those services are live.

## Heroku Notes

- Auction uses the Heroku container stack and `bidmart-auction-service-rust/heroku.yml`.
