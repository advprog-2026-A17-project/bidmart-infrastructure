# BidMart Deployment Status

This project uses two deployment tracks:

- **Official backend runtime:** VPS Docker Compose, with private gRPC for auction → catalogue/wallet.
- **Fallback/rubric runtime:** Heroku HTTP deployments and pipelines.
- **Frontend:** Vercel Production and Preview deployments.
- **Monitoring:** Grafana Cloud Metrics Endpoint plus local Prometheus/Grafana.

## gRPC requirement

The auction service must prefer:

```env
CATALOGUE_GRPC_URL=http://catalogue-service:9091
WALLET_GRPC_URL=http://wallet-service:50051
```

`scripts/verify-grpc-private.sh` is the deployment gate for this. It fails if catalogue/wallet gRPC ports are published to the host or if auction is missing those env vars.

## Observability (production)

| Layer | Platform | Notes |
|-------|----------|-------|
| Metrics scrape | **Grafana Cloud** | Scrape HTTPS `/actuator/prometheus` or `/metrics` on VPS gateway paths or Heroku fallback endpoints |
| Dashboards | Grafana Cloud | Import JSON from `monitoring/grafana/dashboards/` |
| Local dev | Docker Compose | `prometheus` + `grafana` services unchanged |

Setup: [monitoring/grafana-cloud/README.md](../monitoring/grafana-cloud/README.md).  
Targets template: [monitoring/prometheus/prometheus-heroku.yml](../monitoring/prometheus/prometheus-heroku.yml).

**After backend deploy:**

1. Run `USE_DOCKER=true ./scripts/verify-monitoring.sh` on the VPS.
2. Configure Grafana Cloud scrape jobs with Basic Auth.
3. Import dashboards; verify `up{job=~"bidmart-.*"}` in Explore.
4. Screenshot evidence for rubric.

Prometheus/Grafana containers are not deployed as Heroku dynos.

## Promotion gate

Promote staging to production only after:

```bash
./scripts/verify-grpc-private.sh
USE_DOCKER=true ./scripts/verify-monitoring.sh
BIDMART_GATEWAY_URL=https://bidmart-staging.43.157.208.68.sslip.io node scripts/functional-smoke.mjs
```

Then merge/promote the same commit to `main`; production VPS CD runs after CI and the same checks are repeated against the production URL.
