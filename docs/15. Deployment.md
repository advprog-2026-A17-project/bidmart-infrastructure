# BidMart Deployment Status

This project uses platform-managed deployments:

- Backend services: Heroku GitHub automatic deploys.
- Frontend: Vercel GitHub automatic deploys.
- Databases: Supabase Postgres.
- GitHub Actions: CI only. There are no repo-managed CD workflows.

## Live Services

| Service | Platform | URL | Status |

  - `SPRING_DATASOURCE_URL=jdbc:postgresql://aws-1-ap-southeast-2.pooler.supabase.com:5432/postgres?sslmode=require`

- Also set: `AUTH_JWT_SECRET`, `AUTH_INTERNAL_SERVICE_TOKEN`, `REDIS_*` (Redis Cloud addon), `SPRING_RABBITMQ_*` (CloudAMQP)
- First deploy: Flyway may exceed Eco boot timeout; finish migrations via pooler then restart dyno.

## Observability (production)

| Layer | Platform | Notes |
|-------|----------|-------|
| Metrics scrape | **Grafana Cloud** (free) | Scrape HTTPS `/actuator/prometheus` or `/metrics` on each Heroku app |
| Dashboards | Grafana Cloud | Import JSON from `monitoring/grafana/dashboards/` |
| Local dev | Docker Compose | `prometheus` + `grafana` services unchanged |

Setup: [monitoring/grafana-cloud/README.md](../monitoring/grafana-cloud/README.md).  
Targets template: [monitoring/prometheus/prometheus-heroku.yml](../monitoring/prometheus/prometheus-heroku.yml).

**After all backend apps are live:**

1. `USE_HEROKU_URLS=true ./scripts/verify-monitoring.sh` (set URLs in `.env`)
2. Configure Grafana Cloud scrape jobs
3. Import dashboards; verify `up{job=~"bidmart-.*"}` in Explore
4. Screenshot evidence for rubric

Prometheus/Grafana containers are **not** deployed as Heroku dynos.

## Heroku Notes

- Prefer **container** stack (`heroku stack:set container`) + `heroku.yml` for Docker deploys.
- Auth may still be on buildpack until migrated to container.
- Auction and wallet use `heroku.yml` + `Dockerfile` (no BuildKit cache mounts — Heroku-compatible).
- Typical dyno: `web=1:Eco`.
